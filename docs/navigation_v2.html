§1Model details

ONE-HealthRecord v2.0 is a composite of one rule-based component (audit reference) and four learned components: MedGemma 4B as the frozen base extractor, two species-class LoRA adapters trained on top of it, and a gradient-boosted risk model for zoonotic-cluster prediction.

Base model
MedGemma 4B
LoRA adapters
2 × 8.4M params
Risk model
LightGBM v1.0
Training topology
Swarm Learning

§1.3MedGemma veterinary adaptation

Three layers used together. Each layer is justified against the floor set by the layer below it.

Species router

Structured species block prepended to every dictation. Causal attention forces the model to condition on species from the first token.

RAG over vet corpora

FAISS index over Merck Vet Manual, FDA Green Book, USDA APHIS, VeNom-SNOMED crosswalk. Top-k=5 retrieval per dictation.

Species-class LoRA

Two ~8.4M-param adapters (companion / production) trained on synthetic vet notes via DP-SGD. Selected at inference by species class.

§10Caveats & recommendations

An accountability surface only works if it is honest about limits. The full card lists ten in §10; three of the most important are below.

1. The 8.6 percentage-point AUC gap on tribal-land data is a deployment blocker for that population until closed.
2. DP-SGD at ε=8.0 is a training-run guarantee, not a per-prediction guarantee. Production deployment requires a query budget on top.
3. All evaluation is on synthetic data. Production deployment requires re-validation on real records under IRB protocol.
