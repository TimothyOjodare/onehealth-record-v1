# Synthetic Data Notice

**Every patient, household, animal, encounter, condition, and provider record
in this repository is entirely synthetic.**

## What "synthetic" means here

- All data is generated by deterministic Python scripts in `src/data_generation/`
  using `random.Random(seed=42)`. Re-running the pipeline produces the same
  dataset, bit-for-bit.
- No real patient was sampled, anonymized, de-identified, or otherwise
  involved in the creation of this dataset. There is no underlying real
  dataset that this synthetic one was derived from.
- Names are generated from US Census surname-frequency distributions plus
  given-name pools chosen to match Arizona demographic distributions.
  Resemblance to any real person is statistically expected and entirely
  coincidental.
- Addresses use real Arizona ZIP codes and county names paired with
  procedurally-generated street addresses. None correspond to a real
  residence.
- Dates of birth, encounter dates, lab results, vital signs, and clinical
  narratives are all procedurally generated to be epidemiologically
  plausible against published Arizona disease-prevalence patterns.

## Calibration vs. real data

The synthetic dataset is **calibrated** against published Arizona public-
health epidemiology — Maricopa County valley fever rates, Apache County
Rocky Mountain Spotted Fever rates, Coconino County plague enzootic
rates, southern-border brucellosis patterns. The relative shape of the
data matches reality. The absolute values are demo-calibrated and do not
reflect any specific population.

Where rates were deliberately inflated above population-proportional (to
make rare diseases visible in a 970-person sample), the inflation is
documented in the `_caveat` field of the relevant output file in
`data/synthetic/`.

## Names of real institutions

This repository references real Arizona institutions by name:
  - Tucson Medical Center
  - Banner Health (Phoenix, Mesa)
  - HonorHealth Scottsdale
  - IHS Whiteriver Service Unit
  - Northern Arizona Healthcare
  - Arizona Department of Health Services (ADHS)
  - Apache Tribal Health Authority
  - USDA APHIS Veterinary Services
  - CDC NNDSS

These references appear in the institutional-login mockup, the federation
manifest, and various message templates. **They do not represent real
agreements, partnerships, integrations, or endorsements from any of these
organizations.** The real institutions had no involvement in the creation
of this repository. The names are used because the project is geographic-
ally specific to Arizona and the institutional landscape of the state is a
public fact.

Production deployment of any of the patterns demonstrated here would
require Memoranda of Understanding, IRB approval, tribal-IRB partnerships,
data-use agreements, and SMART-on-FHIR identity-provider integration with
each named organization. None of these exist for this MVP.

## Pre-deployment validation pathway

The pathway from this synthetic-data MVP to a real-data deployment is
documented in section 5 of `docs/model_card.md`. The summary:

  1. Pre-deployment validation at a partner academic medical center
     (n = 1,000 retrospective encounters, two-rater annotation, IRB-
     approved data-use agreement).
  2. Tribal IRB partnership with Apache and Navajo nation health
     authorities, with a sovereignty-preserving data-flow protocol.
  3. Production federation with three pilot partner sites for six
     months with quarterly audit review.
  4. Live integration with ADHS-MEDSIS for real reportable-disease
     submission, with parallel-processing windows.

None of these are in scope for the capstone. The capstone is the
architectural foundation. The deployment chain is the next phase of the
work.

## For reviewers

If you are a member of the certification panel or an external reviewer:

  - Every claim in the model card and presentation deck is reproducible
    from `data/synthetic/` and `src/`. The seed is documented; the
    pipeline is one command.
  - If you find any artifact in this repository that appears to contain
    real protected health information, please notify the project author
    immediately. To the author's knowledge, no such content exists.
  - For questions about the synthetic data generation methodology, see
    `src/data_generation/` and the model card section 1.
